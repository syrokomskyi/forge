## What this repository is

This is a **system hub**: it coordinates the product repositories around it but ships no product code itself. The canonical member roster lives in `system/products.yaml` (committed: `id`, `remote`, `offers[]`, `frozen`), the local checkout map in `system/products.local.yaml` (gitignored — machine-local), the allowed/forbidden contract matrix in `system/edges.yaml`, and cross-product work in `queue/`.

## Member registry

- Register a product with `system.product.register --id <kebab> --remote <url> --folder ../<dir>`; adopt a folder of forge repositories at once with `system.product.register --discover` (scans the parent directory, skips `ignored[]`, `@`-worktrees, and remote-less candidates). Preview with `--dry-run`.
- `system/products.local.yaml` is gitignored per-machine state — recreate it by re-running `system.product.register --folder` on each checkout machine.
- `frozen: true` members are pinned by contract — health reports stay informational, never error.
- `ignored[]` names siblings that are deliberately not products (frozen snapshots, test clones) — it silences the unregistered-sibling warning.

## Health sweep

- `system.products.status` reports each member against disk reality: resolved folder, declared profile, `forge.syncedVersion` vs this hub's baseline, dirty state, live `@`-worktrees, commits ahead — plus registry-vs-disk warnings for unregistered forge siblings and git checkouts without `forge.yaml`.
- `system.map.validate` is the registry contract gate (the integration gate runs it) — run it after any `system/` edit.

## Frictions

- Frictions about **this hub's own machinery** are repo-level: `friction.add`.
- Frictions about **member repos or the folder as a whole** are folder-level: `friction.add --level folder` — records carry `origin` + `migratedFrom` provenance and live in this repo's `docs/frictions/`.

## Task queue

## RTK — Token Optimization

Always prefix shell commands with `rtk` to minimize token consumption. RTK filters and compresses command output before it reaches the LLM context, cutting up to 90% of bash output on common operations.

```bash
rtk git status
rtk pnpm test
rtk ls src/
rtk grep "pattern" src/
rtk find "*.ts" .
```

Meta commands:

```bash
rtk gain              # Show token savings
rtk gain --history    # Command history with savings
rtk discover          # Find missed RTK opportunities
rtk proxy <cmd>       # Run raw (no filtering, for debugging)
```

Use default RTK settings only — do not enable `--ultra-compact` or aggressive `read` modes unless the operator explicitly requests it.
