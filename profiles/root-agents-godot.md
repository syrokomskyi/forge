## C# Rules

- Use UTF-8 without BOM, LF, and 4 spaces for indentation.
- Follow existing `.editorconfig` and neighboring code style.
- Public types, methods, properties, and signals: `PascalCase`.
- Private fields: `_camelCase`.
- Do not add new global state without necessity.
- Prefer explicit dependencies via `[Export]`, constructor initialization for plain C# classes, or node composition — instead of tree search on every frame.
- Do not use `GetNode()` in `_Process()` or `_PhysicsProcess()`; cache required nodes in `_Ready()`.
- Respect the Godot lifecycle: `_EnterTree`, `_Ready`, `_ExitTree`, `_Process`, `_PhysicsProcess`.
- All event and signal subscriptions must be properly disconnected when the subscriber node is destroyed, if the subscriber's lifetime may be shorter than the publisher's.
- Do not block the main thread with long operations, file I/O, or network requests.

## Performance

- Place physics logic in `_PhysicsProcess`; visual/per-frame logic in `_Process`.
- Avoid memory allocations, LINQ, node lookups, and resource loading in hot paths.
- Do not optimize prematurely: keep code clear and measurable first.
- Consider pooling for frequently created objects only after profiling or when creation frequency is known to be high.

## RTK — Token Optimization

Always prefix shell commands with `rtk` to minimize token consumption. RTK filters and compresses command output before it reaches the LLM context, cutting up to 90% of bash output on common operations.

```bash
rtk git status
rtk dotnet build
rtk dotnet test
rtk ls scenes/
rtk grep "pattern" scripts/
```

Meta commands:

```bash
rtk gain              # Show token savings
rtk gain --history    # Command history with savings
rtk discover          # Find missed RTK opportunities
rtk proxy <cmd>       # Run raw (no filtering, for debugging)
```

Use default RTK settings only — do not enable `--ultra-compact` or aggressive `read` modes unless the operator explicitly requests it.
