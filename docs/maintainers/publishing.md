# Publishing @warpgogol/forge

## How it works

1. The source lives in the [warpgogol/werkstatt](https://github.com/syrokomskyi/werkstatt) monorepo under `packages/forge/`.
2. [`@warpgogol/repo-extract`](https://github.com/syrokomskyi/repo-extract) extracts the package into the standalone [syrokomskyi/forge](https://github.com/syrokomskyi/forge) repository, flattening to repo root and stripping workspace dependencies.
3. The generated GitHub Actions CI workflow (`.github/workflows/ci.yml`) runs on every push to `main`: lint → typecheck → build → test → `npm publish --provenance --access public`.
4. The `NPM_TOKEN` secret must be set in the [repository settings](https://github.com/syrokomskyi/forge/settings/secrets/actions).

## Triggering a new release

From the werkstatt monorepo root:

```sh
pnpm run publish:forge patch   # or: minor | ALLOW_MAJOR_BUMP=1 pnpm run publish:forge major
```

`scripts/publish-forge.mjs` (RFC-1252) is the **only** supported export path. In one run it:

1. Bumps `packages/forge/package.json` + `forge.yaml` `syncedVersion` and commits the bump into HEAD — `--from-head` exports committed content only, so an uncommitted bump would silently export the old version.
2. Runs `repo-extract --from-head --no-push` into `../packages/forge`.
3. Verifies the extracted repo with `scripts/verify-extract.mjs` — the same script surface standalone CI runs (install, lint, typecheck, build:check, test, build) plus a changelog gate that requires a `[<version>]` section in `CHANGELOG.md`.
4. Pushes to `github.com:syrokomskyi/forge.git`. On a non-fast-forward rejection it reconciles once with `merge -s ours` (the local tree stays the authoritative export) — never force-push.
5. CI on GitHub picks up the push and publishes to npm automatically.

**Do NOT invoke `repo-extract` directly for releases** — it bypasses verification and the clean-source contract. `--skip-verify` exists only as an explicit, loud operator override.

After CI completes, verify the new version on [npmjs.com/package/@warpgogol/forge](https://www.npmjs.com/package/@warpgogol/forge).

## Version

The version in `packages/forge/package.json` is the source of truth. Do NOT set `versionBump` in `extract.config.yaml` — `repo-extract` applies it on top of the monorepo version, causing auto-increment on every extract.

## publishConfig

`publishConfig` in `package.json` overrides local exports with `dist/` paths during `npm publish`. The `dist/` directory is built by CI before publishing.

## CI

The CI workflow is generated by `repo-extract` from `generateCiWorkflow` in `packages/repo-extract/src/fs/transform.ts`. Changes to the embedded `.github/workflows/ci.yml` are overwritten on the next extraction — edit the generator, not the embedded file.
